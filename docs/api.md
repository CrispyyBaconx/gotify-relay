# Gotify Relay API Reference

Base URL: `https://relay.example.com`

## Authentication

All endpoints use Bearer token auth in the `Authorization` header.

There are two token types with disjoint permissions:

- **Caller tokens** — auto-generated by the relay on startup. Used by external applications to send alerts. Can only access `POST /alert/{channel}`.
- **Member tokens** — configured per member. Used by people to manage their subscriptions and retrieve caller tokens. Can access `GET /callers`, `GET /channels`, `GET /subscriptions`, `PUT /subscriptions/{channel}`, `DELETE /subscriptions/{channel}`.

```
Authorization: Bearer <token>
```

## Endpoints

### POST /alert/{channel}

Send an alert to all members subscribed to a channel.

**Auth:** caller token (must have permission for the target channel).

**Request body:**

```json
{
  "title": "optional title",
  "message": "required message body",
  "priority": 5,
  "extras": {}
}
```

- `message` (string, required): alert body.
- `title` (string, optional): alert title.
- `priority` (int, optional): Gotify priority level. Defaults to 0.
- `extras` (object, optional): arbitrary key-value pairs forwarded to Gotify.

Unknown fields are rejected (returns 400).

**Response body:**

```json
{
  "channel": "alerts",
  "results": [
    {"target": "alice", "ok": true},
    {"target": "bob", "ok": true},
    {"target": "carol", "ok": false, "error": "push to member \"carol\" failed with status 401"}
  ]
}
```

**Status codes:**

| Code | Meaning |
|------|---------|
| 200  | All subscribed members received the alert (or no members subscribed). |
| 207  | Partial success — some members received it, some failed. |
| 400  | Invalid JSON, unknown fields, or missing `message`. |
| 401  | Missing or unknown caller token. |
| 403  | Caller token is valid but not permitted for this channel. |
| 404  | Channel does not exist. |
| 502  | Every Gotify push failed. |

### GET /callers

List all callers with their auto-generated tokens and allowed channels.

**Auth:** member token.

**Response:**

```json
{
  "callers": [
    {"name": "my-app", "token": "auto-generated-token", "channels": ["alerts"]}
  ]
}
```

Use this endpoint to retrieve caller tokens for external applications.

### GET /channels

List all available channels.

**Auth:** member token.

**Response:**

```json
{
  "channels": [
    {"name": "alerts", "default_subscribed": true}
  ]
}
```

### GET /subscriptions

List the authenticated member's current subscription state.

**Auth:** member token.

**Response:**

```json
{
  "subscriptions": [
    {"channel": "alerts", "subscribed": true}
  ]
}
```

### PUT /subscriptions/{channel}

Subscribe to a channel.

**Auth:** member token.

**Response:**

```json
{"channel": "alerts", "subscribed": true}
```

### DELETE /subscriptions/{channel}

Unsubscribe from a channel.

**Auth:** member token.

**Response:**

```json
{"channel": "alerts", "subscribed": false}
```

### GET /healthz

Health check. No authentication required.

**Response:** 204 No Content (empty body).

## Error format

All error responses return JSON:

```json
{"error": "description of what went wrong"}
```

## Gotify comparison

The relay accepts the same JSON body shape as Gotify's `POST /message` endpoint, but routing and auth differ:

| Aspect | Gotify native | Relay |
|--------|--------------|-------|
| Endpoint | `POST /message?token=<app_token>` | `POST /alert/{channel}` |
| Auth | App token in query string | Bearer token in header |
| Routing | One user per app token | Fan-out to all subscribed members |
| Body | `{title, message, priority, extras}` | Same |
